# Model card — Replica

## 1. Model overview

Replica fits Cox proportional hazards models for overall survival and DFS/RFS in two breast cancer cohorts. The models are audit instruments, not clinical devices. The primary comparison is a clinical baseline (age, stage, ER, PR) versus the same baseline plus PAM50 subtype. A secondary model adds IntClust within METABRIC. An NMF module analysis summarizes expression programs.

## 2. Intended use

- Research replication and methods demonstration.
- Comparing subtype systems under a fixed, pre-specified protocol.
- Teaching censoring-aware permutation tests, NPC, and external validation.
- Generating aggregate evidence for a dashboard or manuscript.

## 3. Out-of-scope use

- Individual patient diagnosis, prognosis, or treatment selection.
- Clinical decision support, triage, or insurance decisions.
- Any use with children, pregnant patients, or non-breast cancers.
- Any claim that a subtype *causes* a survival difference.
- Re-identification or linkage with identifiable data.

## 4. Features

The clinical baseline uses age per 10 years, stage III/IV vs I/II, ER positive vs negative, and PR positive vs negative. The subtype model adds three dummy variables for LumB, Basal, and HER2, with LumA as reference. TCGA grade is not available in the public export and is excluded from the primary model; METABRIC grade is used only in a sensitivity analysis. HER2 is used only in METABRIC sensitivity analyses.

## 5. Training and validation

The discovery cohort is TCGA-BRCA PanCancer Atlas. The external validation cohort is METABRIC. The discovery model is fitted once on the complete-case TCGA OS cohort and locked. No METABRIC outcome is used to select features, tune the model, or choose the subtype system.

Incremental value is evaluated with 5-fold cross-validated predictions within each cohort, stratified by event status. The same folds are used for the clinical and clinical + subtype models. External transport uses the locked TCGA coefficients and METABRIC risk scores.

## 6. Metrics

- Kaplan–Meier curves by subtype.
- Log-rank statistic with a censoring-aware permutation p-value.
- Cox hazard ratios with 95% confidence intervals.
- Harrell's C-index with a bootstrap 95% interval.
- Out-of-fold ΔC-index with a paired bootstrap interval.
- Likelihood-ratio test for the subtype terms.
- Calibration at 60 months and a calibration slope.
- BH/BY adjusted p-values for the module family; permutation maxT is implemented and unit-tested.
- NPC Liptak p-value calibrated against the joint permutation distribution; Fisher and Tippett combiners are implemented and unit-tested.

## 7. Evaluation results

The frozen results are in `artifacts/results.json` and `artifacts/tables/`. The dashboard reports the primary scorecard before any exploratory result. The headline decision is generated by code, not hand-written:

- **Replicated and incremental** if subtype separation survives BH in both OS cohorts, Basal HR > 1 in both, the incremental LR q < 0.05 in both, and the paired ΔC CI excludes 0 in both.
- **Replicated but not incremental** if separation replicates but ΔC does not.
- **Cohort-specific** if only one cohort separates.
- **Not replicated** otherwise.

The exact values are in the artifact, not duplicated here, so the model card cannot drift from the analysis.

## 8. Limitations

The model is observational. Proportional hazards is an assumption, not a fact; the audit reports it but does not test every possible violation. The subtype labels are not assay-identical across cohorts. The clinical covariates are coarse. Complete-case analysis can bias estimates. The C-index is a discrimination metric and says nothing about calibration or clinical utility. The calibration slope is estimated on the validation cohort and is therefore a descriptive transport diagnostic, not a re-fit.

## 9. Ethical considerations

Breast cancer subtype labels have been used to justify treatment differences. A replication audit can inform that use, but it cannot settle it. The dashboard avoids individual prediction and avoids language that implies clinical readiness. The code is MIT licensed; the data remain governed by the source cohorts.

## 10. Maintenance

The pipeline is versioned through `config/analysis.yaml`. Changing a primary parameter requires a new configuration version and an entry in `docs/audit_log.md`. The CI runs unit tests on every push. The public API is read-only and serves frozen artifacts.
